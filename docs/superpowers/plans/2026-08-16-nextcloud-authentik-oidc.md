# Nextcloud SSO via Authentik OIDC — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nextcloud 34 on tower authenticates users against Authentik on fastpi via OIDC, with the `cloud-users` group deciding who gets access.

**Architecture:** Authentik gets a `cloud-users` group, an OAuth2/OIDC provider, an application, and a policy binding that refuses non-members before a token is issued. Authentik config is applied as a git-tracked **blueprint** (matching the existing `ak apply_blueprint` pattern) rather than by clicking through the UI. Traefik gains a `cloud.holy-grail.ch` route to tower:8080 reusing the existing `tower-wake-public` WoL middleware. Nextcloud gets reverse-proxy settings plus the `user_oidc` app.

**Tech Stack:** Authentik 2026.5.2 (Django/Postgres, `ak` CLI, blueprints), Traefik file provider, Cloudflare Tunnel (dashboard-managed), Nextcloud 34.0.3 on Unraid, `user_oidc` app.

**Design doc:** `docs/superpowers/specs/2026-08-16-nextcloud-authentik-oidc-design.md`

---

## Split of responsibility

There is no SSH key from fastpi to tower (`Permission denied (publickey,password,keyboard-interactive)`), and the Cloudflare tunnel is token-based so its hostnames live in the Cloudflare dashboard.

- **Tasks 1–3, 7** run on fastpi — fully automatable here.
- **Task 4** is Cloudflare dashboard — user only.
- **Tasks 5–6** run on tower — user only, unless SSH access is set up first.

Tasks 1–3 can be completed before the user touches anything; nothing breaks until the Traefik route and the Cloudflare hostname both exist.

## File structure

- **Create** `Docker/Authentik/blueprints/nextcloud-oidc.yaml` — declarative Authentik config (group, provider, application, policy binding). Secret-free and committable; client ID/secret are generated by Authentik and read back, never written here.
- **Create** `Docker/Traefik/traefik/dynamic/nextcloud.yml` — router, headers middleware, service pointing at `192.168.1.101:8080`.
- **Modify** `Docker/Authentik/authentik-config-export.yaml` — refreshed snapshot after applying the blueprint.
- **Modify** `Docker/Authentik/README.md` — note the new blueprint.

- [ ] **Step 1: Introspect the current model fields**

```bash

print()
print('SUB_MODE CHOICES:', OAuth2Provider._meta.get_field('sub_mode').choices)
print()
print('REDIRECT_URIS FIELD:', OAuth2Provider._meta.get_field('redirect_uris'))
print()
print('BINDING FIELDS:', [f.name for f in PolicyBinding._meta.get_fields()])
print()
print('FLOWS:', list(Flow.objects.values_list('slug', flat=True)))
print()
print('CERTS:', list(CertificateKeyPair.objects.values_list('name', flat=True)))
print()
print('SCOPE MAPPINGS:', list(ScopeMapping.objects.values_list('name','scope_name')))
" 2>/dev/null | tail -30
```

Expected: a field list including `redirect_uris`, `sub_mode`, `client_type`, `authorization_flow`, `invalidation_flow`, `signing_key`, `property_mappings`; flow slugs including `default-provider-authorization-explicit-consent`; and the three default scope mappings for `openid`, `profile`, `email`.

Record the exact `sub_mode` value for "user UUID" (expected `user_uuid`) and the exact authorization/invalidation flow slugs — the next step uses them verbatim.

- [ ] **Step 2: Write the blueprint**

Use the flow slugs, cert name and scope-mapping names observed in Step 1. `client_id`/`client_secret` are deliberately **omitted** so Authentik generates them — this keeps the committed file secret-free, consistent with `export-config.sh`.

```yaml
version: 1
metadata:
  name: nextcloud-oidc
  labels:
    blueprints.goauthentik.io/description: |
      Nextcloud SSO. Access is gated by the cloud-users group binding at the
      bottom of this file - remove it and every Authentik user gets Nextcloud.
      client_id/client_secret are generated by Authentik, NOT stored here.
entries:
  # ---- Access group ----
  - model: authentik_core.group
    id: cloud-users-group
    identifiers:
      name: cloud-users
    attrs:
      is_superuser: false

  # ---- OIDC provider ----
  - model: authentik_providers_oauth2.oauth2provider
    id: nextcloud-provider
    identifiers:
      name: Nextcloud
    attrs:
      authorization_flow:
        !Find [authentik_flows.flow, [slug, default-provider-authorization-explicit-consent]]
      invalidation_flow:
        !Find [authentik_flows.flow, [slug, default-provider-invalidation-flow]]
      client_type: confidential
      sub_mode: user_uuid
      include_claims_in_id_token: true
      redirect_uris:
        - matching_mode: strict
          url: https://cloud.holy-grail.ch/apps/user_oidc/code
        - matching_mode: strict
          url: https://cloud.holy-grail.ch
      signing_key:
        !Find [authentik_crypto.certificatekeypair, [name, authentik Self-signed Certificate]]
      property_mappings:
        - !Find [authentik_providers_oauth2.scopemapping, [scope_name, openid]]
        - !Find [authentik_providers_oauth2.scopemapping, [scope_name, profile]]
        - !Find [authentik_providers_oauth2.scopemapping, [scope_name, email]]

  # ---- Application ----
  - model: authentik_core.application
    id: nextcloud-app
    identifiers:
      slug: nextcloud
    attrs:
      name: Nextcloud
      provider: !KeyOf nextcloud-provider
      meta_launch_url: https://cloud.holy-grail.ch
      policy_engine_mode: any

  # ---- THE ACCESS GATE ----
  # Group-scoped binding: only cloud-users members may obtain a token.
  - model: authentik_policies.policybinding
    identifiers:
      target: !KeyOf nextcloud-app
      group: !KeyOf cloud-users-group
      order: 0
    attrs:
      enabled: true
```

### Task 3: Add the Traefik route

**Files:**
- Create: `/home/pi/Projects/Docker/Traefik/traefik/dynamic/nextcloud.yml`

- [ ] **Step 1: Write the route**

Follows `audiobookshelf.yml`, with two deliberate differences: the service points at an off-box IP rather than a container name, and **no `Content-Security-Policy` header is injected** — Nextcloud sends its own and an injected one breaks the web UI. The `tower-wake-public` middleware already exists in `tower-wake.yml`.

```yaml
# Nextcloud on tower (192.168.1.101), published via Cloudflare Tunnel -> Traefik.
#
# tower sleeps. The tower-wake-public chain (defined in tower-wake.yml) rate
# limits first, then fires a WoL packet and holds the request behind a
# self-refreshing page until tower:8080 answers. The rate limit matters here
# specifically because this router is public - without it any internet scan
# becomes a power switch for the server.
#
# Deliberately NO Content-Security-Policy: Nextcloud sends its own and an
# injected policy breaks the web UI. This differs from audiobookshelf.yml.
http:
  routers:
    nextcloud:
      rule: "Host(`cloud.holy-grail.ch`)"
      entryPoints: ["websecure"]
      priority: 1
      service: nextcloud
      middlewares:
        - tower-wake-public
        - nextcloud-secure-headers
      tls:
        certResolver: cloudflare

  middlewares:
    nextcloud-secure-headers:
      headers:
        stsSeconds: 31536000
        stsIncludeSubdomains: true
        stsPreload: true
        contentTypeNosniff: true
        referrerPolicy: "strict-origin-when-cross-origin"
        frameDeny: false
        customFrameOptionsValue: "SAMEORIGIN"
        permissionsPolicy: "camera=(), microphone=(), geolocation=()"
        customResponseHeaders:
          Server: ""

  services:
    nextcloud:
      loadBalancer:
        servers:
          - url: "http://192.168.1.101:8080"
        passHostHeader: true
```

### Task 5: Configure Nextcloud for the reverse proxy — USER ACTION

Run on tower. On Unraid, `occ` runs inside the Nextcloud container; substitute the real container name from `docker ps`, and the `www-data` user may differ by image (linuxserver images use `abc`).

**Do this before Task 6.** Without `overwriteprotocol=https`, Nextcloud builds `http://` redirect URIs and the strict OIDC match in Authentik fails.

- [ ] **Step 1: Add the trusted domain**

```bash
docker exec -u www-data nextcloud php occ config:system:get trusted_domains
docker exec -u www-data nextcloud php occ config:system:set trusted_domains 2 --value=cloud.holy-grail.ch
```

Use the next free index — if `trusted_domains` already lists two entries (indices 0 and 1), `2` is correct; adjust to avoid overwriting an existing entry.

- [ ] **Step 2: Set the proxy overrides**

```bash
docker exec -u www-data nextcloud php occ config:system:set overwrite.cli.url --value=https://cloud.holy-grail.ch
docker exec -u www-data nextcloud php occ config:system:set overwritehost --value=cloud.holy-grail.ch
docker exec -u www-data nextcloud php occ config:system:set overwriteprotocol --value=https
docker exec -u www-data nextcloud php occ config:system:set trusted_proxies 0 --value=192.168.1.2
```

- [ ] **Step 3: Pin the upload chunk size under Cloudflare's 100MB cap**

Cloudflare's free tier rejects any single request over 100MB. Nextcloud chunks uploads, but the default chunk can exceed that, producing a 413 on large files. 20MB is comfortably under.

```bash
docker exec -u www-data nextcloud php occ config:app:set files max_chunk_size --value=20971520
```

- [ ] **Step 4: Verify the overrides took**

```bash
docker exec -u www-data nextcloud php occ config:system:get overwriteprotocol
docker exec -u www-data nextcloud php occ config:system:get overwritehost
curl -s https://cloud.holy-grail.ch/status.php
```

Expected: `https`, `cloud.holy-grail.ch`, and the version JSON with no untrusted-domain error.

- [ ] **Step 5: Confirm the real proxy address**

If logins later show every request coming from one IP, or `trusted_proxies` looks wrong, check what tower actually sees rather than trusting the `192.168.1.2` assumption:

```bash
docker logs nextcloud --tail 20 | grep -oE '^[0-9.]+' | sort -u
```

Set `trusted_proxies 0` to whatever address appears.

### Task 6: Install and configure user_oidc — USER ACTION

**Keep the local Nextcloud admin account and password login enabled throughout.** This is the break-glass path if OIDC misbehaves.

- [ ] **Step 1: Install the app**

Nextcloud web UI → Apps → search "OpenID Connect user backend" (`user_oidc`) → Download and enable. Or:

```bash
docker exec -u www-data nextcloud php occ app:install user_oidc
```

- [ ] **Step 2: Register the Authentik provider**

Using the `CLIENT_ID` and `CLIENT_SECRET` from Task 2 Step 4:

```bash
docker exec -u www-data nextcloud php occ user_oidc:provider authentik \
  --clientid="<CLIENT_ID>" \
  --clientsecret="<CLIENT_SECRET>" \
  --discoveryuri="https://sso.holy-grail.ch/application/o/nextcloud/.well-known/openid-configuration" \
  --scope="openid profile email nextcloud" \
  --mapping-uid=sub \
  --mapping-display-name=name \
  --mapping-email=email \
  --mapping-groups=groups \
  --group-provisioning=1 \
  --unique-uid=0
```

If the `occ user_oidc:provider` subcommand is unavailable in the installed version, configure the identical values in Settings → Administration → OpenID Connect instead: Identifier `authentik`, the client ID/secret, the discovery endpoint above, scope `openid profile email nextcloud`, User ID mapping `sub`, Display name mapping `name`, Email mapping `email`, Groups mapping `groups`, "Use group provisioning" **on**.

The custom `nextcloud` scope carries the groups claim. Without it in the scope list, `cloud-admins` members get no admin rights.

- [ ] **Step 3: Verify the provider registered**

```bash
docker exec -u www-data nextcloud php occ user_oidc:provider
```

Expected: a row for `authentik` with the discovery URI.

## Rollback

If OIDC misbehaves, log in with the local Nextcloud admin (never disabled) and:

```bash
docker exec -u www-data nextcloud php occ app:disable user_oidc
```

To remove the Authentik side, delete the `Nextcloud` application and provider and the `cloud-users` group in the Authentik UI, then `git revert` the blueprint commit. Removing the Traefik route is `rm Docker/Traefik/traefik/dynamic/nextcloud.yml` — the file provider hot-reloads.
