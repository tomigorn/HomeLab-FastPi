# Authentik SSO MVP — Design / Spec

**Date:** 2026-06-07
**Project:** `/home/pi/Projects/Docker/Authentik`
**Goal (MVP):** Stand up Authentik as an OIDC identity provider and inject SSO login into **Portainer** and **Audiobookshelf**, with two user groups — **admin** and **streaming**.

This supersedes the abandoned `infrastructure-OLD/authentik` attempt (left untouched as an archive).

---

## 1. Scope

**In scope (MVP):**
- Authentik core stack (PostgreSQL + server + worker) on a fresh project, exposed at `https://sso.holy-grail.ch`.
- Two groups: `admin`, `streaming`.
- OIDC login for **Audiobookshelf** (native OIDC, already public) and **Portainer CE** (generic OAuth, VPN/LAN-only).
- Group → application access bindings.
- Declarative configuration via Authentik **blueprints** so the setup is reproducible and version-controlled.

**Explicitly deferred (NOT this MVP):**
- Invitation links / self-enrollment flows.
- Social login brokering (Google / Microsoft / Apple).
- Enforced TOTP/WebAuthn 2FA (Authentik supports it; not configured in MVP).
- *arr apps, download clients, SMB/LDAP.

Users are created manually in the Authentik admin UI for now.

## 2. Architecture

### 2.1 Containers (project `Authentik`)
- **`authentik-postgresql`** — `docker.io/library/postgres:16-alpine`, data in a named/local volume. Internal only.
- **`authentik-server`** — `ghcr.io/goauthentik/server:2026.5.2`, command `server`. Joined to BOTH `authentik_internal` (DB) and external `traefik_proxy` (so Traefik can reach it). Listens on `:9000` (HTTP). No host ports published (Traefik fronts it).
- **`authentik-worker`** — same image, command `worker`. Joined to `authentik_internal`. Mounts blueprints + media. Runs blueprint application and background tasks.

> **No Redis.** Authentik removed Redis in 2025.10; 2026.5 needs only PostgreSQL. Any older template with a Redis service is obsolete.

### 2.2 Networks
- `authentik_internal` — new bridge, internal DB/worker traffic.
- `traefik_proxy` — existing external network; `authentik-server` joins it.

### 2.3 Reverse proxy / exposure
- New Traefik file route `Traefik/traefik/dynamic/sso.yml`: `Host(\`sso.holy-grail.ch\`)` on `websecure`, `tls.certResolver: cloudflare`, secure-headers middleware, service → `http://authentik-server:9000`, `passHostHeader: true`.
- **Cloudflare Tunnel** (dashboard-managed): user adds public hostname `sso.holy-grail.ch` mirroring the existing `audiobookshelf.holy-grail.ch` target.
- Authentik trusts the Docker bridge as proxy (default trusted CIDRs cover `172.16.0.0/12`); set `AUTHENTIK_LISTEN__TRUSTED_PROXY_CIDRS` only if needed.

### 2.4 Bootstrap / secrets (in `.env`, gitignored)
- `AUTHENTIK_SECRET_KEY` — random 50+ char.
- `AUTHENTIK_POSTGRESQL__HOST/NAME/USER/PASSWORD` (+ `PG_*` for the postgres container).
- `AUTHENTIK_BOOTSTRAP_PASSWORD` — initial `akadmin` password (first boot only).
- `AUTHENTIK_BOOTSTRAP_TOKEN` — initial API token (first boot only).
- `AUTHENTIK_BOOTSTRAP_EMAIL` — admin email.
- `PORTAINER_OIDC_CLIENT_ID` / `PORTAINER_OIDC_CLIENT_SECRET`.
- `ABS_OIDC_CLIENT_ID` / `ABS_OIDC_CLIENT_SECRET`.

The two client secrets are generated by us and injected into the blueprint via `!Env`, so they are known up front and pasted straight into Portainer/ABS — no UI secret-scraping.

## 3. Declarative configuration (blueprint)

A custom blueprint `blueprints/mvp.yaml` mounted into the worker (and server) under `/blueprints/custom/`, applied at startup as one atomic transaction. It creates:

1. **Groups:** `admin`, `streaming`.
2. **Custom property/scope mapping `abs-groups`** (for Audiobookshelf role mapping): expression returns a `groups` claim —
   - if user is a member of `admin` → `["admin"]`
   - else → `["user"]`
   This matches ABS's group-claim role mapping (`admin` → Admin, `user` → User).
3. **OAuth2/OIDC Provider + Application — Audiobookshelf:**
   - `client_id`/`client_secret` from env.
   - Redirect URIs: `https://audiobookshelf.holy-grail.ch/auth/openid/callback` and `.../auth/openid/mobile-redirect`.
   - Scopes: openid, email, profile + `abs-groups` mapping.
   - Application bound to groups `admin` + `streaming`.
4. **OAuth2/OIDC Provider + Application — Portainer:**
   - `client_id`/`client_secret` from env.
   - Redirect URI: `https://portainer.fastpi.homelab/` (Portainer derives its callback from its base URL).
   - Scopes: openid, email, profile.
   - Application bound to group `admin` only.
5. Both providers reference the existing default signing key and standard scope mappings via `!Find`.

## 4. Portainer routing (VPN/LAN-only)

- Add `portainer` to the `traefik_proxy` network (compose edit). Keep its existing `:9443` host port as a LAN fallback.
- New route `Traefik/traefik/dynamic/portainer.yml`: `Host(\`portainer.fastpi.homelab\`)` on the **`internal`** entrypoint + an `ipAllowList` middleware (LAN `192.168.1.0/24` + `172.24.0.0/16`, mirroring `wg-easy.yml`/`dashboard.yml`). Service → `http://portainer:9000` (Portainer HTTP listener).
- OIDC redirect base = `https://portainer.fastpi.homelab` — resolvable on LAN and via WireGuard; the Docker-management UI is never exposed to the internet.

## 5. App-side wiring (user performs, exact values provided)

### Audiobookshelf (Settings → Authentication → OpenID Connect)
- Issuer: `https://sso.holy-grail.ch/application/o/audiobookshelf/`
- Auto-discover, or endpoints under that issuer.
- Client ID / Secret: from `.env`.
- Group Claim: `groups`; enable "Automatically create new users".
- Redirect URIs already registered in Authentik.

### Portainer (Settings → Authentication → OAuth, custom provider)
- Authorization URL: `https://sso.holy-grail.ch/application/o/authorize/`
- Access token URL: `https://sso.holy-grail.ch/application/o/token/`
- Resource/userinfo URL: `https://sso.holy-grail.ch/application/o/userinfo/`
- Redirect URL: `https://portainer.fastpi.homelab`
- Client ID / Secret: from `.env`; Scopes: `openid email profile`; User identifier: `preferred_username`.
- **One-time:** after the first admin user logs in via OAuth, an existing Portainer admin promotes them to admin (CE has no group→role mapping).

---

## 6. Known limitations / risks

- **Portainer CE** cannot map OIDC groups to roles/teams (Business-only) → manual one-time admin promotion. Login injection itself works in CE.
- **Audiobookshelf** group→role mapping depends on the `groups` claim values; verify on the deployed ABS version (a known bug ignores the advanced-permissions claim for admins in some 2.32.x builds — not used here, we only map account type).
- **First-boot secrets** (`AUTHENTIK_BOOTSTRAP_*`) are read only once; document them.
- Blueprint client secrets are real secrets → `.env` is gitignored; `.env.example` carries placeholders only.

---

## 7. Acceptance criteria

1. `docker compose up -d` in `Authentik/` brings up postgres + server + worker healthy; `https://sso.holy-grail.ch` shows the Authentik login; `akadmin` logs in.
2. Blueprint applied: groups `admin` + `streaming`, both applications, and bindings exist in the admin UI.
3. A test user in `streaming` can log into Audiobookshelf (regular user) and **cannot** see/access Portainer.
4. A test user in `admin` can log into Audiobookshelf (Admin) and into Portainer (after one-time promotion).
5. Portainer is reachable only on LAN/VPN (`portainer.fastpi.homelab`), not on the public internet.
6. Project follows the repo's 4-file convention; secrets are gitignored.
